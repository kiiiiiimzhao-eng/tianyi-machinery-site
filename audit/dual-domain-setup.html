双域名运营配置说明

湖北天宜机械 · 更新于 2026-08-04 · 策略：两个域名各自独立运营，互不跳转

一、职责划分（最终方案）

域名用途托管在哪谁来维护
tianyimachine.com 新独立站（英文 B2B 官网、产品页、博客、询盘表单） Cloudflare Pages（GitHub 自动部署） 本仓库
tianyi-machinery.com 老站，继续展示产品 + 企业邮箱域名（kim@tianyi-machinery.com） 阿里云 CDN（*.w.cdngslb.com）+ 阿里云企业邮箱（MX：mxn/mxw.mxhichina.com） 原有服务商 / 原有后台
好消息：实测老域名当前解析走的是阿里云 CDN，并没有指向新站，MX 邮件记录也完好。 也就是说——老站和邮箱本来就在正常独立运行，你不需要做任何 DNS 改动。

二、需要做的事（只有 1 件，已由我完成）

✅ 已改：删除仓库里旧域名 → 新域名的 301 规则

项目根目录 _redirects 里原本写了 4 条「tianyi-machinery.com/* 跳转到 tianyimachine.com」的规则。 这是按「老域名退役」思路写的，与你现在「两站独立」的方案冲突，已删除。现在该文件只保留：

  • www.tianyimachine.com → tianyimachine.com（新站自己的 www 归一，必须保留）

你只需在 GitHub Desktop 点一次 Push origin，Cloudflare 会自动重新部署。

三、绝对不要做的事

动作后果结论
在 Cloudflare Pages 里把 tianyi-machinery.com 添加为自定义域 老域名会开始显示新站内容，老站被顶掉 禁止
开启 Cloudflare Email Routing（邮件路由） 会覆盖 mxhichina 的 MX 记录，kim@ 邮箱立刻收不到信 禁止
做跨域 Bulk Redirect（老域名 301 到新域名） 老站直接消失 禁止
把老域名的 NS 切到 Cloudflare 没必要；切换过程若漏记录会同时打断老站和邮箱 不建议
如果你之前已经把 tianyi-machinery.com 添加进了 Cloudflare 站点列表： 只要 没有把域名的 NS（名称服务器）改成 Cloudflare 给的那两条，它就一直是 Pending 状态、不生效。 建议直接在 Cloudflare 里把这个站点 Remove Site 删掉，避免以后误操作。

四、询盘怎么进邮箱（不需要任何 DNS 设置）

  1. 页面上的邮箱链接：全站页脚 / 联系区都是 mailto:kim@tianyi-machinery.com，点击直接唤起客户邮件客户端，走的是客户自己的邮箱，与我方域名配置无关。
  2. 网站表单：新站表单用的是 Web3Forms（access key c6eeec07-…）。收件人是你在 Web3Forms 后台绑定的邮箱地址，只要那里填的是 kim@tianyi-machinery.com，询盘就会进这个邮箱。
  3. 因此：新站 ≠ 需要邮箱域名。两者完全解耦。
建议做一次实测：上线后到新站联系表单填一条测试询盘提交，确认 kim@tianyi-machinery.com 能收到（注意查垃圾箱，首次可能被判垃圾，标记「非垃圾」即可）。

五、两站并行的 SEO 注意事项

  • 内容不要照搬。两个站如果产品文案高度雷同，Google 会判重复内容，通常只收录其中一个、另一个降权。建议新站主打英文外贸长文＋博客，老站保留原有内容体系，不要把新站文案复制过去。
  • 各自 canonical 指向自己。新站所有页面 canonical 已统一为 https://tianyimachine.com/...；老站的 canonical 保持指向老域名，不要互相指。
  • 不要互相做大量页脚全站互链。首页放一个「集团/关联站点」入口即可，避免被判操纵链接。
  • Search Console 分别提交。两个域名各自验证、各自提交 sitemap，数据独立看。
  • 公司名、地址、电话、股票代码（832654）等 NAP 信息两站要一致，这对本地/企业实体识别是加分项。
